# COLAB-FIRST STRATEGY (read before editing):
#
# The Colab notebook's Cell 3 runs, verbatim and un-editable:
#     apt-get install -y -q ta-lib          # harmless no-op on Ubuntu (check=False)
#     pip install -q -r requirements.txt    # MUST succeed (check=True)
#
# So this file must `pip install` cleanly on a STANDARD Colab runtime
# (Python 3.11/3.12, Linux x86_64, CUDA torch + numpy 2.x preinstalled) with NO
# system C libraries to build. The pins below are chosen for exactly that:
#
#   • TA-Lib  : >=0.6.7 ships PREBUILT manylinux cp311/cp312 wheels, so
#               `pip install TA-Lib` needs NO TA-Lib C source build and NO
#               apt package. (0.4.x linked against a C lib that apt does not
#               provide, which is what broke Cell 3.) TA-Lib stays the indicator
#               single source of truth (DESIGN_DECISIONS.md #3).
#               If you are ever on a platform with NO prebuilt wheel, run
#               scripts/colab_setup.sh first to build the TA-Lib C library.
#
#   • numpy   : <3.0 (NOT <2.0). Colab preinstalls numpy 2.x alongside its CUDA
#               torch; pinning <2.0 forced a downgrade that conflicted with the
#               whole preinstalled stack. faiss-cpu>=1.9 and TA-Lib>=0.6.7 both
#               support numpy 2.x, so we allow it.
#
#   • faiss-cpu : >=1.9 relaxed its numpy pin to "numpy<3,>=1.25" (1.8.0.post1
#               hard-pinned numpy<2.0 — the root of the resolver conflict). faiss
#               is optional and import-guarded at runtime (jordan/repo_indexer).
#
#   • torch   : floor only (>=2.2), NOT a hard ==pin. Colab already ships a CUDA
#               build of torch; a hard pin would try to reinstall/override it and
#               can break CUDA. A floor lets Colab keep its own wheel while still
#               guaranteeing a recent-enough API for local/dev installs.
# ─────────────────────────────────────────────────────────────────────────────
